# 审计

<ContractNote file="openapi.yaml" />

## 记录的内容

认证事件——登录成功与失败、OAuth 登录、登出、口令重置、MFA 失败、权限拒绝、
限流违规、账号上锁与解锁。

写入方遵守两条规则：

- **绝不阻塞请求。** 写入是 fire-and-forget；失败只打日志，用户的操作照常完成。
- **绝不记录凭据。** 只记 action、分类、状态、IP、User-Agent 和少量非敏感上下文。

## 审计端点

<ApiTable tag="Audit" />

看板与报表查询接受时间窗口参数。服务端会对该参数做上限截断，因此一个过大的 `days`
值得到的是一个有界窗口，而不会触发全表扫描。

## 两条必须写明的限制

::: warning 审计日志不防篡改
<Status kind="planned" /> 它就是一张普通数据库表。没有哈希链，没有 checkpoint。
任何有数据库写权限的人都能改它而不留痕迹。

**不要在任何假定完整性保护的场合把它当作证据。**
:::

::: warning 归因指向 user 行，不是身份根
<Status kind="planned" /> 人类事件归因到 `user_id`。架构要求归因应当落在身份根上，
这样它才能在账号的其它一切都变化时保持稳定。

AI 主体的认证已经归因到身份根了，人类那几条路径还没迁移。
:::

两条都是[一致性读数](/zh/project/status)里「已写好但尚未成立」的不变式——
`f4` 与 `f1`。
