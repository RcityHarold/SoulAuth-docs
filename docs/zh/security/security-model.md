# 安全模型

SoulAuth 保护什么、怎么保护，以及它的责任在哪里终止。

## 它保护什么

三件事，此外没有：

1. **静态凭证**：读到数据库的人不因此获得以任何人身份认证的能力。
2. **认证判定**：一个身份主张不能被伪造、重放或提权。
3. **归因**：谁在何时、以何种方式完成了认证的记录。

**你的**应用的授权不在这张表上。认证成功说的是「是谁」，不授予任何东西。
[身份与权限的边界](/zh/spec/identity-vs-authority)

## 静态凭证

| 秘密 | 怎么存 |
|---|---|
| 口令 | Argon2 |
| MFA 备用码 | Argon2，逐条校验 |
| TOTP 密钥 | ChaCha20-Poly1305，必须可逆，因为算验证码要用它 |
| 客户端密钥 | Argon2 |
| PKCE verifier | SHA-256，常数时间比较 |
| 会话令牌 | SHA-256 指纹 |
| OIDC 访问与刷新令牌 | SHA-256 指纹 |
| 授权码 | SHA-256 指纹 |
| 口令重置令牌 | SHA-256 指纹 |
| 邮箱验证令牌 | SHA-256 指纹 |

<Status kind="tested" guard="conformance::b4b" /> 断言上面这些列都不存明文，
而且哈希函数是真哈希而不是某种编码。

### 为什么用两种不同算法

口令熵低且由人选定，因此让离线爆破变贵的只能是慢哈希，也就是 Argon2。

Bearer 令牌是 32 字节随机值或已签名 JWT。没有什么可猜的，而且它们在**每一个已认证
请求**上都要被查一次。慢哈希在那里买不到任何安全，却会压垮认证路径。SHA-256 才是
正确选择，而对两种情况选不同算法是刻意的，不是不一致。

### 会话那一条值得单说

`session.token` 曾经保存的是完整签名 JWT，与客户端手中那一枚逐字节相同：
一次数据库读取就等于系统里所有在线会话。现在保存的是指纹，同样满足吊销查询。

## 认证判定

**口令。** Argon2，并在启动时算好一个哑哈希，使得对不存在账号的登录与对真实账号的
登录耗时相同。

**MFA。** TOTP，并按用户持久化一个重放水位线，因此同一个验证码不能被重用，
跨副本也不行。

**锁定与限流。** 按账号与按 IP 两个维度，都存在数据库里，因此跨副本共享。

**AI 主体。** 对服务端签发的一次性挑战做 Ed25519 签名。带域分隔、绑定 issuer，
所以一枚签名既不能被重放到别的用途，也不能被重放到别的部署。挑战在验签**之前**
被消费，关掉了并发使用的窗口。[AI 原生身份](/zh/concepts/ai-native-identity)

**OIDC。** 授权码流程，强制 PKCE（只有 `S256`）。刷新令牌轮换；复用一枚已消费的
令牌被当作泄露处理，吊销整个令牌族。

## 设计不会越过的边界

**服务无法改自己的表结构。** SoulAuth 不发任何 DDL；两个 SQL 文件由运维导入。
一个能改写自己表结构的认证服务，也能改写自己的约束。

**错误不泄露内部。** 数据库与服务器错误统一收敛成一个 `internal_error` 码。
账号不存在与口令错误不可区分。引导端点对「令牌错误」与「已初始化」返回同一状态码，
因此失效令牌无法用来探测部署状态。

**对 Agent 只持公钥。** SoulAuth 从不持有 Agent 的私钥。与口令哈希不同，
存着的那个值连离线攻击的目标都算不上。

## 它到哪里为止

<Status kind="planned" /> **审计不防篡改。** 一张普通表，没有哈希链、没有 checkpoint。
任何有数据库写权限的人都能静默改它。不要拿它当证据。

<Status kind="planned" /> **吊销在副本之间有延迟**，最多一个缓存 TTL。

**传输层是你的。** SoulAuth 对非环回地址拒绝明文，但 TLS 终止、证书、网络隔离
是部署方的事。

**你应用的授权是你的。** 这里的 RBAC 治理的是 SoulAuth 自己的控制平面。

**没有任何认证资质。** 没有标准组织评估过这里的任何东西。
