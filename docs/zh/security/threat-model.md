# 威胁模型

具体攻击、什么挡住了它，以及什么没挡住。

## 数据库被读走

**攻击者拿到一份数据库拷贝。**

他拿到：邮箱、用户名、Argon2 口令哈希、加密的 TOTP 密钥、Ed25519 **公**钥，
以及每一枚 bearer 凭证的 SHA-256 指纹。

他做不到：以任何人身份认证。指纹不是令牌，公钥不是私钥。
<Status kind="tested" guard="conformance::b4b" />

他能做到的，只要有足够时间：离线爆破弱口令。Argon2 让这件事变贵，但不是不可能，
口令策略仍然要紧。

::: warning 除非他还拿到了 `JWT_SECRET`
TOTP 密钥用 `MFA_SECRET_ENCRYPTION_KEY` 加密。如果那把密钥从未被显式设置，
它**从 `JWT_SECRET` 派生**。于是一份数据库转储加上环境文件，就能算出可用的
TOTP 验证码。非环回的 `APP_URL` 强制要求专用密钥，理由正在于此。
:::

## 会话令牌被窃

**令牌经由日志、代理或 XSS 泄露。**

它在过期或被吊销之前一直有效。系统不绑定 IP 或设备，这是刻意的省略：
这两样挡住合法用户（尤其在移动网络上）的次数，比挡住攻击者更多。

缓解手段：把 `JWT_EXPIRATION` 调短；有怀疑就登出；盯审计日志里某个会话
从不合理地址出现。

<Status kind="planned" /> 吊销在一个缓存 TTL 之内到达其它副本。

## 授权码被拦截

**攻击者从重定向里截到了码。**

PKCE 挡住它。没有 `code_verifier` 这个码毫无用处，而 verifier 从不离开合法客户端。
`S256` 是强制的，且不提供 `plain`，因为 `plain` 对这件事完全不提供保护。

同样必需的是精确匹配的重定向 URI，这样码从一开始就送不到别处去。

## 刷新令牌被窃

**攻击者拿到刷新令牌并兑换。**

轮换让这件事变响而不是变静。后兑换的那一方出示的是一枚已消费的令牌，
而那被当作泄露处理：该客户端与该用户名下的**整个令牌族**被吊销。
合法用户被登出。这既是正确结果，也是一个信号。

## 爆破

**猜口令。**

按账号锁定（默认 5 次、15 分钟）加按 IP 限流，都在数据库里，因此跨副本共享。

Argon2 让每次尝试在服务端也很贵。登录耗时用哑哈希拉平，使得不存在的账号与
口令错误不可区分。

## 账号枚举

**摸清哪些地址已注册。**

- 登录：未知账号与口令错误，同样的错误、同样的耗时。
- 口令重置：永远返回成功。发信失败被吞掉而不是抛出，因为只对已注册地址返回 500
  本身就成了那个 oracle。
- 引导：「令牌错误」与「已初始化」返回同一状态码。
- AI 主体挑战：未知主体与已停用主体，同样的错误。

## 跨 provider 接管

**攻击者用一个 `sub` 为 `"4001"` 的 Google 账号，去攻击数字 id 为 `4001` 的
GitHub 用户。**

绑定按 `(provider, provider_subject)` 成对匹配。只按 subject 匹配会让这两者成为
同一个主体。这不需要任何利用代码，只需要标识符恰好撞上。

同一条规则也适用于**你**：把用户键在 `(iss, sub)` 上，绝不只用 `sub`。

## 恶意的 OIDC 客户端

**有客户端管理权限的人加了一个自己控制的重定向 URI。**

协议层面挡不住这件事：能改 `redirect_uris` 的人就能劫持任意登录。
它靠权限收敛：`soulauth:oidc_clients.write` 默认只授予 `admin`，且每次改动都写审计。

把那条权限当作等同于完全账号访问来对待，因为它就是。

## 伪造客户端 IP

**客户端设置 `X-Forwarded-For` 以绕开 IP 限流。**

只有在 `TRUST_PROXY_HEADERS=true` **并且** SoulAuth 能绕过代理被访问时才可能。
绑在环回上，让代理成为唯一入口。

它默认关闭，理由就是这个。

## 重放 Agent 签名

**攻击者捕获了一次已签名的挑战应答。**

四道防线全在被签名的那几个字节里：nonce 一次性且在验签前就被消费；它绑定到唯一
一个主体；issuer 在 payload 里，所以来自另一个部署的签名验不过；带版本的域分隔符
意味着它不能被重放到别的用途上。[那四行](/zh/concepts/ai-native-identity)

## 你应用里的 XSS

**攻击者脚本在你的页面上运行。**

这不是 SoulAuth 能阻止的事。它能改变的是爆炸半径：

- **BFF**：令牌在服务器一侧，`HttpOnly` cookie 脚本读不到。
- **公开客户端**：令牌在浏览器里，脚本执行等于完全失守。

这个差别就是选 [BFF](/zh/integrate/browser-and-bff) 的主要理由。

## 不防的

明说出来，因为一份只列胜绩的威胁模型不算威胁模型：

- **主机被攻陷。** 服务器上的 root 能从环境里读到 `JWT_SECRET`。
- **恶意运维。** 任何有数据库写权限的人都能不留痕迹地改审计日志。
  <Status kind="planned" />
- **拒绝服务。** 限流保护的是凭证，不是可用性。
- **依赖的供应链攻击。**
- **钓鱼。** MFA 提高成本，不消除它。
